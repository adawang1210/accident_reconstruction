# 軌跡平滑化 — 方法研究與選型

**問題**：目前的平滑（Savitzky-Golay，`ground_footprint.savgol_smooth`）還是會抖、偶爾出現
不合常理的路徑。**根因**：SG 是「局部多項式降噪濾波」，**沒有物理模型**——它不知道車不能
瞬移、不能橫向急跳（jerk）、不能超過轉彎半徑。所以雜訊大或片段短時它仍會 wiggle，也擋不住
違反運動學的軌跡。

學界對「物理上合理的車輛軌跡重建」有明確更好的做法，依對本專案的契合度排序如下。

## 方法一覽

### ① Kalman + RTS 平滑器（本專案採用）

用**運動模型當先驗**：等加速（CA）或等轉率+等加速（CTRA）模型跑前向 Kalman，再跑後向
Rauch–Tung–Striebel（RTS）遞迴。一次同時輸出**平滑的位置＋速度＋加速度**，內建**連續速度/
加速度**約束——這正是「合乎常理」的關鍵。gap 由 predict 步自然帶過；量測雜訊 `r` 與過程雜訊
`q` 兩個參數調平滑度。

- 為何選它：純 NumPy 可寫、無新依賴；線性 CA 模型在 2D 下**過彎不切角**（加速度向量在轉彎時
    指向向心方向，x/y 各自的 CA 模型即可表現轉彎）；輸出帶速度可直接餵下游。
- 來源：[Kalman 平滑演算法](https://www.researchgate.net/publication/371892418_Trajectory_Smoothing_Algorithm_Based_on_Kalman_Filter)、
    [RTS 平滑器原理](https://www.emergentmind.com/topics/rauch-tung-striebel-smoother)、
    [CCTV 車流軌跡擷取用 CA+RTS](https://arxiv.org/pdf/2004.01288)。

### ② 兩步法：先除離群、再平滑（一併採用作前處理）

平滑「之前」先用 **jerk（三階導）或加速度偵測並剔除不合理跳點**，平滑器才不被尖峰帶歪。
剔除的點在 Kalman 裡當「無量測」→ 只 predict。這補強現有的「峰值速度守門」。

- 來源：[兩步法 + 小波](https://onlinelibrary.wiley.com/doi/full/10.1002/eng2.13090)、
    [改良離群偵測 + 平滑](https://www.spiedigitallibrary.org/conference-proceedings-of-spie/13018/3024008/Two-step-vehicle-trajectory-reconstruction-strategy-based-on-an-improved/10.1117/12.3024008.full)。

### ③ 最小 jerk / 最小曲率 樣條（後來也採用，接在 ① 之後）

擬合一條在容差內貼合觀測、但**最小化 jerk/曲率**的樣條（quintic spline 保證 jerk 連續）。
直接對付「不合常理」——真人開車走最小曲率路徑。與 ① 效果相近但較難處理 gap 與非等時取樣。

> 原本列為備選，實際上 ① 單獨做不到「圖上是平滑曲線」——jerk 合格的軌跡仍可能是鋸齒。
> 現以 `fit_smooth_curve`（二階懲罰的平滑樣條，在真實時間軸上解，天然吃 gap 與非等時取樣）
> 接在 ① 之後當最後一層，見下方 §③。

- 來源：[Quintic 樣條](https://www.mdpi.com/2032-6653/16/8/434)、
    [最小曲率最佳化](https://arxiv.org/pdf/2309.09186)、
    [限制平滑樣條](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/10571921)。

### ④ 車道約束平滑（本專案獨門優勢，待 CAD 線接上）

有 **CAD 車道幾何**後，把軌跡拆成**沿車道（弧長）＋橫向偏移**，只重壓橫向分量（車基本沿
車道走）——橫向抖動被壓、縱向進程不動。最強的物理先驗，一般平滑器做不到。留待
[3D CAD 線](3D_RECONSTRUCTION.md)接上後當最後一層。

- 來源：[車道約束路徑平滑](https://link.springer.com/article/10.1186/s43067-025-00272-3)、
    [人類偏好路徑模型](https://link.springer.com/article/10.1007/s42154-023-00259-8)。

## 怎麼量「是否變合理」（客觀指標）

研究界用 **jerk（三階導）大小、jerk 變號次數、|jerk|>15 m/s³ 的比例**衡量物理合理性
（有論文把 raw 的 jerk 從 ±4900 壓到 ±45）——[加速度去噪](https://onlinelibrary.wiley.com/doi/10.1155/2023/2661136)。
本專案用「平均 |jerk|、最大 |jerk|、jerk 變號次數」比較 SG vs Kalman-RTS。

## 採用與實作

`accident_reconstruction/trajectory_smoothing.py`：

- `kalman_rts_smooth`：2D 等加速 Kalman + RTS 平滑（per-axis，處理非等時 dt 與 gap）。
    由 `auto_reconstruct.smooth_metric` 包裝，作為 `project_metric` 的**無條件最後一段**，
    取代 Savitzky-Golay。管線順序是 **anchor 修正 → 峰值守門 → 平滑 → 空缺補值 → 再平滑**。
- `fit_smooth_curve`：**形狀**平滑（懲罰最小平方／Whittaker 平滑樣條），跟在 Kalman 之後，
    是 `smooth_metric` 的最後一段。見下方 §③。
- `trajectory_jerk`：驗收指標（平均/最大 |jerk|、變號次數、frac>15）。
- `turn_angles_deg` / `lateral_accelerations`：**形狀**驗收指標（每點轉向角、側向加速度）。
- `reject_kinematic_outliers`：獨立診斷工具（硬加速度上限）。**不被平滑器使用**。

### 實作中踩到、修掉的坑

1. **速度初始化**：原本 velocity 初始化為 0，快速物體會嚴重延遲；改用**前幾點最小平方
    擬合斜率**（對雜訊穩健，單點差分在首步小於雜訊時連正負號都會錯）。
2. **離群剔除方式**：不能對「原始位置的二次差分加速度」設門檻——像素雜訊微分兩次會讓
    幾乎每個點看起來都是「超大加速度離群」（實測在測試軌跡上砍掉 60 點中的 58 點、把路徑
    壓平）。改成 **Kalman innovation gating**：只有當量測值離模型預測超過 `gate_sigma`（5σ）
    才跳過該點——這才是正確做法（抓真跳點、留正常雜訊）。

### 實測（BMW，在地輪廓 anchor 原始軌跡上）

指標 `frac>15` = |jerk|>15 m/s³ 的幀比例（越低越合乎常理）：

|                     | jerk 平均 | frac>15    | 路徑位移 |
| ------------------- | --------- | ---------- | -------- |
| Savitzky-Golay 汽車 | 216       | **92%** ❌ | 1.7 cm   |
| **Kalman+RTS 汽車** | **3.6**   | **5%** ✅  | 6.4 cm   |
| Savitzky-Golay 機車 | 480       | **91%** ❌ | 2.5 cm   |
| **Kalman+RTS 機車** | **3.1**   | **0%** ✅  | 12.7 cm  |

SG 只壓振幅、**九成的幀仍不合運動學**；Kalman+RTS 把 jerk 降約 60–150 倍、`frac>15` 從 92%
降到 5%（機車 0%），路徑僅移數公分（忠實不失真），且**過彎不切角**（合成正弦曲線 err 0.007，
低於雜訊底 0.033）。

## 後續修正（涵蓋率與序列化）

上面那張表只成立於「平滑真的有跑到」的軌跡。六個場景逐車輛稽核後發現兩個破口，皆已修掉。

### ① 平滑曾被綁在輪廓修正裡，13 條軌跡只有 6 條吃得到

`kalman_rts_smooth` 原本是 `refine_metric_from_contours` 內的「第 3 層」，於是有三條路徑
會靜默跳過它：場景沒有 `contact_contours.npz`（keelung、宜蘭娃娃車，共 4 條）、該車輛沒有
輪廓、以及**峰值速度守門退回 legacy anchor 時**——守門退回的是**完全未平滑的原始軌跡**
（pre_impact car、taoyuan car2、yilan car）。

改法：抽出 `smooth_metric`，作為 `project_metric` 的無條件最後一段；守門只決定「用哪個
anchor」，不再連帶決定「要不要平滑」。另外在補值**之前**先對守門勝出的軌跡平滑一次——
`interpolate_straight_gaps` 是用缺口前後的**航向是否一致**來判斷該不該補，餵原始 anchor
會讓航向估計太雜訊，把轉彎誤判成直行（實測會多補 BMW 3 個原本正確拒絕的缺口）。

「補值後再平滑」也順手解掉了原本的已知殘留：補值插入的線性段與平滑曲線在邊界不 jerk-連續，
BMW 機車最終 `frac>15` 曾因此從 0% 回到約 11%。

### ①-b 把平滑套到原始 anchor 上，卻讓濾波器發散了

①「讓平滑跑到每條軌跡」是對的，但它把**在 BMW 上手調的 `meas_std = 0.08 m` 套到從未驗證過
的原始軌跡**。BMW 的 anchor 經過輪廓修正，確實精確到公分級；沒有輪廓側檔的場景、以及峰值
守門退回 legacy anchor 的車輛，用的是**原始單應投影 anchor，噪音是公尺級**。宣告 8 公分的
量測噪音，等於叫 innovation gating 把真實量測當離群值丟掉——實測 **83–91% 的幀被拒絕**，
濾波器沒有量測可用，就靠等加速模型自由外推。

13 條軌跡有 7 條因此離開資料：宜蘭五結的 car **反向**跑掉 57 m，台南永康的 car 偏離 105 m。

**這個失效騙過了原本的驗收指標。** 發散的輸出是完美平滑的（mean |jerk| ~4），所以上一版這裡
的表格把「jerk 從 15277 降到 4.4」寫成成果，實際上有一部分只是**輸出不再跟隨量測**。低 jerk
是平滑正確的必要條件，不是充分條件。

改法有三：

1. `estimate_measurement_std` 逐軌跡估計 `meas_std`，取代全域常數。用二階差分的 **p90**
    （非中位數）——地面噪音沿軌跡並不均勻，遠處的像素 anchor 經過條件更差的單應區域，中位數
    只描述乾淨的多數。
2. `kalman_rts_smooth` 末端加**發散守門**：平滑後若**中位數**偏離超出預算就整條退回輸入
    （用中位數而非最大值，才不會把「正確拒絕單一尖峰」誤判成發散）。
3. 預算另受軌跡自身路徑長 50% 的上限約束——短又雜訊大的軌跡（宜蘭 18 幀的行人：1.8 m 行走
    對上 0.39 m 噪音）訊噪比小於 1，濾波器會改信模型而外推。

修正後，量測拒絕率 91%/88%/83% → 49%/38%/12%，且**最終輸出與原始投影的端點距離，13 條有
11 條落在 ±11% 內**——平滑忠於資料。全 13 條軌跡（原始 → 修正後，量自交付的 CSV）：

| 場景       | 車輛                      | mean \|jerk\|                     | frac>15                     |
| ---------- | ------------------------- | --------------------------------- | --------------------------- |
| keelung    | taxi / police_car         | 8358→5.5 / 15253→12.9             | 99%→2% / 100%→35%           |
| pre_impact | car / motorcycle          | 8315→9.0 / 3424→10.9              | 81%→13% / 81%→29%           |
| taoyuan    | car / car2                | 2846→6.3 / 14450→8.2              | 100%→9% / 100%→24%          |
| yilan      | car / motorcycle / person | 15277→8.6 / 16644→8.7 / 49969→7.7 | 92%→12% / 97%→16% / 100%→0% |
| BMW        | car / motorbike           | 854→5.4 / 1262→5.9                | 89%→8% / 79%→6%             |

數字比上一版「漂亮」得少，但這次是**真的**：軌跡同時合乎運動學**且**貼著量測。

**已知殘留（模型限制，非參數問題）**：逐條檢查後，剩下的最大偏離無一例外落在**撞擊之後**
或**軌跡末端**——宜蘭機車 7.6 m 在撞擊後 5 幀且正好是最後一幀、桃園 car 3.4 m 在撞擊後
13 幀。等加速先驗表達不了脈衝式碰撞（騎士被撞飛），RTS 在端點也沒有後續資料可約束。正解是
**以撞擊幀為界分段平滑**，因為速度在撞擊瞬間本來就不連續。`process_std` 仍是全域常數，
下一步可由單應性 Jacobian 逐幀給 per-sample `R`、並用 NIS 檢定自動調。

另外，宜蘭的 person 在圖上是 18 幀走 11.1 m（≈62 km/h），這**不是平滑造成的**——原始投影
本身就是 10.4 m，屬於該物件的追蹤／單應問題。

### ② 序列化把平滑成果吃掉

三階微分會把量化誤差放大 fps³。CSV 的 lat/lon 原本寫 7 位小數（≈1.1 cm）、reconstruction
JSON 的 `x_m`/`z_m` 寫 3 位（1 mm），於是**前端與網頁地圖讀到的根本不是平滑後的軌跡**：

| BMW car，同一條軌跡                     | mean \|jerk\|  | frac>15        |
| --------------------------------------- | -------------- | -------------- |
| 記憶體 metric                           | 2.8            | 0%             |
| reconstruction.json（3 位 → **5 位**）  | 21.7 → **2.8** | 72% → **0%**   |
| route_recognized.csv（7 位 → **9 位**） | 455 → **3.9**  | 91% → **1.2%** |

`route_csv_row` 改 `:.9f`（≈0.1 mm）、`build_reconstruction` 的軌跡樣本改 `round(_, 5)` /
`round(_, 9)`。KML 維持 7 位——它只給 Google Earth 顯示，不會被微分。

### ③ jerk 合格、圖上仍是鋸齒——「合乎運動學」不等於「形狀平滑」

②修好之後，13 條軌跡的 jerk 與貼合度都通過了，README 的辨識軌跡圖卻**仍然是鋸齒狀**。
兩件事並不矛盾，是**驗收指標漏了一整個面向**。

**根因：jerk 是時間導數，看不見「步長小於雜訊」的軌跡。** BMW 的 car 192 幀只走 5.5 m，
每幀不到 3 cm，而殘留 anchor 雜訊也差不多是這個量級。這時候：

- **位置誤差**很小（幾公分）→ 貼合度過關；
- **jerk** 是位置誤差除以 dt³，也很小 → 4.5 m/s³，運動學過關；
- 但**航向**＝橫向抖動 ÷ 步長，兩者同量級 → **每幀甩幾十度**。

那個逐幀甩動的航向，就是圖上的鋸齒。所以「平滑」必須**直接對形狀設條件**，不能只管運動學。

另一種形狀缺陷是**彎肘（elbow）**：航向在 8 幀內轉 30°，每幀只有 3.75°，逐點轉向角看不出來，
畫出來卻是兩段直線接在一個角上。擋掉它的不是幾何而是**物理**——用軌跡自己宣稱的速度過那個
彎，需要的側向加速度不是路面車輛做得出來的。

**做法：Kalman 之後再擬合一條「資料仍允許的最平滑曲線」。**
`fit_smooth_curve` 解懲罰最小平方（Whittaker 平滑器，即離散平滑樣條）：

```
minimise  ||z - y||² + λ ||z''||²        （x、y 共用同一個 λ，在真實時間軸上）
```

解出來是 C² 的樣條曲線；λ 越大二階導越被壓到 0，**極限就是一條直線**——所以直行段出來是直線、
轉彎出來是真正的圓弧。λ **不逐場景手調**：λ 變大時轉向角**下降**、偏離量測**上升**，於是從最弱的
懲罰往上掃，取**第一個同時滿足兩個形狀條件**的解；若都不滿足，取仍在忠實度預算內的最強者。

| 條件       | 門檻             | 取法 | 為什麼                                                                                                       |
| ---------- | ---------------- | ---- | ------------------------------------------------------------------------------------------------------------ |
| 每點轉向角 | p99 ≤ **5°**     | p99  | 車輛 1 秒轉 90°、25 fps，每幀也才 3.6°。取 p99 不取 p95：鋸齒是**局部**缺陷，285 點的軌跡 p95 還放行 14 個點 |
| 側向加速度 | **max ≤ 4 m/s²** | max  | ~0.4 g 是乾燥路面的實務過彎上限。取 max 不取分位數：最尖的彎可以只有**一個點**寬，p99 會直接跨過去           |

### ③-b 這一版把撞擊磨掉了——形狀平滑不能凌駕證據

③ 交付後被指出：**BMW 的機車軌跡跟原始明顯不一樣了。** 屬實，而且錯得很嚴重。

機車軌跡原本是「一條長直線 → 撞擊處急轉 → 另一個方向」。上一版輸出把它變成一條大 C 弧：
**起點位移 1.77 m、路徑長 6.04 m → 3.54 m（縮 41%）、撞擊處的方向改變被完全抹平**。
在事故重建裡，那個方向改變是本案的主要證據，不是雜訊。

**機制**：撞擊處的轉角是**真實**的，它讓轉向角條件**永遠**不合格，於是 λ 一路被推到預算上限，
**整條軌跡陪著一個局部特徵被拉直**。

**為什麼沒被指標抓到**：忠實度預算量的是**中位**偏離，而中位數對「一端被搬走」不敏感——
這條軌跡的中位偏離只有 0.22 m，看起來很體面；真正該看的 `dev_max = 1.77 m` 當時有量到，
但沒有被當成守門條件。中位數是 Kalman 那一段的正確守門（它會剔除離群，本來就該留下一兩個遠點），
對「整體重塑形狀」的擬合則是錯的守門。

三個修正：

1. **以撞擊幀分段擬合**（`_impact_split`）。碰撞是脈衝，速度與航向在該點本來就不連續，
    一條 C² 曲線橫跨撞擊，只能在「否認撞擊」和「自己不合格」之間二選一。分段後兩段各自平滑，
    接縫的轉角自然保留——因為沒有任何約束跨越接縫。
2. **形狀保真上限**（`MAX_SHAPE_DEVIATION_EXTENT = 15%`）：任何一點的位移不得超過該段路徑長的
    15%，且量的是**相對這一段的輸入**（不是 anchor）——問「這一段重塑了多少形狀」，
    就必須以這一段的輸入為基準；拿 anchor 當基準等於把 Kalman 的位移也記到擬合帳上，
    實測會讓四條軌跡額度歸零、平滑完全失效。
3. **驗收指標排除撞擊接縫**（`shape_metrics`）。保留下來的撞擊轉角是**結論**，不是缺陷；
    把它算進去，一條正確的軌跡會報出 36° 轉向與 90 m/s² 側向加速度，全部來自那一個樣本。

修正後，BMW 機車路徑長 6.04 → 5.69 m（−6%）、起點回到原位，撞擊轉角保留。

### ③-c 靜止殘骸的門檻，兩個方向都踩過

轉向角需要排除「沒有方向可言」的短段，門檻設在哪裡踩了兩次雷：

- 設成**中位步長的比例**：對「大部分時間靜止」的軌跡自我失效——BMW 機車撞擊後 106 幀多半是
    停在地上的殘骸，中位步長**就是**靜止抖動本身，於是 0.1 cm 步長上的 19° 「轉彎」
    （圖上四十分之一個像素）否決了每一個候選解。
- 改設成**量測雜訊**：反向壞掉。一條「步長 ≈ 雜訊」的軌跡（正是這一整段存在的理由）所有段
    都被排除，於是沒有東西能不合格，第一個候選就被判定通過——BMW 的 car 原封不動地回傳，
    圖上照樣是鋸齒。

正解是**雜訊的一小部分**（`_STATIONARY_STEP_FRACTION = 0.25`）：足以分開靜止
（殘骸每幀動雜訊的四十分之一）與「慢但真實」的運動。

### ③-d 有一部分鋸齒根本不在資料裡，在繪圖

同一批軌跡，畫成**純線**是乾淨的平滑曲線，畫成 README 的圖卻是鋸齒。差別在
`write_recognized_figure` **每一幀都畫一個半徑 3 px 的實心圓**：車一慢下來，圓點就重疊成
一塊邊緣不規則的粗塊，讀起來就是鋸齒。

改成 `_spaced()`：標記至少間隔一個直徑才畫。原本「顯示取樣密度」的用意保住了
（快則稀、慢則密），但不再由標記去誤導形狀。這個原因在最初的調查裡完全沒被檢查——
一看到鋸齒就假定是軌跡的問題。

**現況（13 條軌跡，段內量測、排除撞擊接縫）**：10 條同時滿足 5° 與 4 m/s²；
3 條未達標（台南永康機車 5.6°、BMW 機車 9.8°、宜蘭娃娃車 car 13.3°），
殘餘粗糙都落在**撞擊之後**的短段。這三條**刻意不再往下壓**：要壓過去就得突破形狀保真上限，
那正是 ③ 犯的錯。資料本身（撞擊後翻滾、追蹤品質下降）就不是平滑運動，
把它擬合成漂亮的曲線是編造而不是重建。
